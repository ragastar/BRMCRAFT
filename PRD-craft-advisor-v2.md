## 1. Что это и зачем

### Одной фразой
Оверлей для PoE 2, который на наведённый предмет отвечает не «сколько стоит», а **«что докрутить, чтобы стоил кратно дороже, каким методом и с какой вероятностью»**.

### Проблема
EE2 и другие прайс-чекеры говорят только текущую цену. Игрок видит «5 дивайнов», но не знает: стоит ли крафтить дальше, какой мод мешает стоить 50, реально ли это добить. Сейчас это ручной анализ через Craft of Exile + трейд + опыт.

### Решение — три слоя поверх готового прайс-чека
1. **Diff** — сравнивает предмет с дорогими аналогами (из trade2), показывает: что хорошо / чего не хватает / какой мод двигает цену.
2. **Feasibility** — можно ли недостающее физически добавить (слоты, iLvl, метод).
3. **Strategy** — человеческий текст плана крафта с методами и вероятностями (Claude API).

### Чего НЕ делаем в v1
- Не строим копию рынка (River API для PoE2 не существует — подтверждено poe.ninja).
- Не автоматизируем крафт/покупку (ToS + не нужно).
- Не делаем монетизацию (бесплатно на старте).
- Не делаем веб-версию (только оверлей; веб — возможная фаза 3).
- Не используем ninja Builds (его в EE2 нет, эталон берём из trade2).

## 2. На чём строим: форк EE2 — реальная карта кода

`Kvan7/Exiled-Exchange-2`, MIT, релиз 0.15.4 (05.06.2026). Electron + Vue + TypeScript, плюс Python (`dataParser`). Структура проверена клонированием.

### Реальные модули (из исходников)
| Путь | Что это по коду | Наша работа |
|---|---|---|

| `renderer/src/web/price-check/trade/common.ts` | `RATE_LIMIT_RULES`, `adjustRateLimits` (синхрон с заголовками GGG), эндпоинт | Встаём в ту же очередь |
| `renderer/src/web/price-check/trade/Cache.ts` | Кеш в памяти, ключ = sha1 тела запроса, TTL из окна лимита | Расширяем до персистентного (см. 5) |
| `renderer/src/web/price-check/trade/RateLimiter.ts` | Скользящее окно, очередь | Не трогаем, используем |
| `renderer/src/web/background/Prices.ts` | Курсы валют. Тянет НЕ ninja напрямую, а готовый дамп с `api.exiledexchange2.dev` (namespace ITEM/GEM/UNIQUE) каждые ~31 мин | Используем для нормализации цен крафта |
| `renderer/src/web/price-check/price-prediction/poeprices.ts` | ML-оценка рарника + `pred_explanation` (вклад мода). PoE2-поддержка под вопросом (FIXME в коде) | Опора, если работает на PoE2 |
| `main/src/proxy.ts` | Локальный HTTP-прокси, **белый список хостов**. Запросы к трейду с `useSessionCookies: true` | **Добавляем хосты сюда** (PoE2DB и т.д.) |
| `dataParser` (Python) | Генерит данные модов/баз | Расширяем весами/тирами для feasibility |
| `renderer/src/web/price-check` (Vue) | UI прайс-чека | Добавляем панель Craft Advisor |

### Как EE2 ходит в сеть (важно для встройки)
Vue не стучится наружу напрямую — зовёт `Host.proxy(...)`, локальный прокси (`main/src/proxy.ts`) идёт в интернет. Хосты вне белого списка режутся (`req.destroy()`). Белый список сейчас: домены pathofexile.com (official), `poe.ninja`, `www.poeprices.info`, `api.exiledexchange2.dev`. **Любой новый источник = новая строка в белом списке.**

### Стек — НЕ ограничиваемся знакомым (по задаче)
Electron + Vue + TS + Python, как в EE2. Не переписываем на Next.js — знакомость не аргумент, а переписывание скелета убивает смысл форка. Код пишет Claude Code.

## 4. Поток анализа одного предмета

Игрок наводит на предмет → hotkey. Воронка от бесплатного к дорогому (экономим лимит trade2):

### Слой 0 — локально, 0 запросов
Парсинг (готово) + данные модов из `dataParser`. Знаем: база, iLvl, занятые/свободные слоты (преф/суфф), моды, тиры, что может выпасть, веса.

### Слой 1 — сужение гипотез, локально
По весам модов (dataParser/PoE2DB) определяем 3–5 модов, которые стоит проверять на цену (низкий вес = редкий/дорогой). Лимит не тратим.

### Слой 2 — trade2 под бюджетом (≤6 запросов)
- 1 поиск: предмет «как есть» → стартовая цена
- 1 поиск: топ дорогих листингов этой базы (sort price asc, читаем дорогой конец) → **эталон** + какие моды у дорогих
- 2–3 поиска: по одному ключевому моду → вклад мода в цену
Каждый кешируется по сигнатуре (раздел 5).

### Слой 3 — diff-движок (НАШЕ)
Сравнение с эталоном из слоя 2:
- **Keep** — что хорошо, не трогать
- **Missing** — чего нет (кандидаты)
- **Value driver** — какой мод даёт кратный скачок (корреляция цен листингов с модом vs без; либо `pred_explanation` от poeprices если работает на PoE2)

### Слой 4 — feasibility (НАШЕ + данные модов)
Для каждого missing: свободный слот есть? проходит по iLvl? метод (эссенция/эксальт/омен/база)? вероятность (веса RePoE)? Логику путей берём из open-source «POE2 How To Craft» (Java → перенос, beam search).

### Слой 5 — strategy (НАШЕ + Claude API)
Расчёт → текст: «Префиксы не трогай. Добей резист холода эссенцией X (≈60%/попытку), поднимет с 5 до ~70 div. Попытка ≈ N div (цена эссенции из дампа валют)».

## 5. Лимиты и кеш — по реальному коду

### Лимиты (НЕ изобретаем — EE2 уже решил)
`common.ts`: стартовые `SEARCH/FETCH = 1 запрос / 5 сек`. `adjustRateLimits` читает заголовки ответа GGG (`x-rate-limit-rules`) и подстраивает лимитер под реальные серверные лимиты. `preventQueueCreation` кидает «Retry after N sec» если очередь > ~1.5с. **Наш движок просто встаёт в эту очередь — отдельной логики лимитов не пишем.**

### Кеш — есть, но в памяти
`Cache.ts`: `Map`, ключ = `hash.sha1(тело запроса)`, TTL = max(300, окно лимита). Сбрасывается при перезапуске приложения и при смене валюты (`purgeIfDifferentCurrency`).

### Что добавляем сами
Для накопления истории «какой мод сколько стоил» нужен **персистентный слой** (SQLite или файл в `%APPDATA%`) — штатный кеш в памяти этого не делает. Ключ — та же сигнатура (база + моды + диапазоны + лига). Это наш код, отдельно от `Cache.ts`.

## 6. Что берём готовым vs пишем сами

### Готовым (из форка)
Парсинг, оверлей, hotkey, UI-каркас, trade2 search+fetch (с модами и тирами!), синхронизация лимитов, кеш в памяти, нормализация цен через курсы валют, прокси с белым списком, данные модов (dataParser), ML-оценка poeprices (если PoE2 ок).

### Пишем сами (= продукт)
1. **Diff-движок** (слой 3) — эталон из trade2-листингов, keep/missing/value-driver
2. **Feasibility** (слой 4) — можно ли скрафтить + вероятности
3. **Strategy / Claude API** (слой 5) — текст стратегии
4. **Персистентное хранилище** (раздел 5) — история цен по сигнатуре
5. **UI-панель** в `renderer/src/web/price-check` — Keep / Missing / Strategy
6. **Доп. хосты в прокси** (`main/src/proxy.ts`) — PoE2DB и пр.

## 8. Риски и открытые вопросы

| Риск | Влияние | Что делать |
|---|---|---|
| Rate limit trade2 / бан сессии | Высокое | Используем штатный лимитер EE2 + бюджет ≤6 + персист. кеш |
| poeprices не работает на PoE2 | Среднее | Value-driver считаем сами из trade2-листингов (корреляция цен) |
| Точность вероятностей крафта | Среднее | Механики 0.5 свежие; помечать оценки приблизительными |
| «POE2 How To Craft» на Java | Среднее | Перенос логики beam search в TS — самый неочевидный кусок |
| Новый источник = правка прокси | Низкое | Добавить хост в белый список `main/src/proxy.ts` |
| Кеш в памяти не копит историю | Низкое | Свой персистентный слой (раздел 5) |

### Открытые вопросы
- poeprices.info на PoE2 — работает или нет (определяет, пишем ли value-driver сами)
- Где «POE2 How To Craft» расходится с механиками 0.5
- Доступ к PoE2DB — API или парсинг (и добавить в белый список прокси)
- Формат вывода вероятностей в UI (число / диапазон / «легко-средне-сложно»)
- **Опционально, фаза 2:** нужна ли агрегация ninja Builds как «эталон меты по билду». Требует своей сборки данных (запрос + парсинг + хост в прокси). В v1 НЕ делаем — эталон из trade2 достаточен.

## 10. РЕАЛИЗОВАНО (as-built, июнь 2026)

Сервис собран как форк EE2, виджет **Craft Advisor** (`renderer/src/web/craft-advisor/`), hotkey **Ctrl+E**. Весь код покрыт unit-тестами (TDD) и проверен **headless-харнессом на живой trade2-сессии** (`specs/craft-advisor/live.test.ts`, запуск `CRAFT_LIVE=1 npx vitest run …/live.test.ts`).

### Поток (что реально работает)
1. **Слой 0** (`layer0.ts`) — парсинг + слоты префиксов/суффиксов, modifiable.
2. **Свойства** (`item-mods.ts`) — реальные строки со значениями из advanced-текста (включая имплициты), а не названия аффиксов.
3. **Слой 2** (`trade-reference.ts` `fetchComparables`) — поиск **сравнимых** колец (count ≥2 твоих модов), выборка 40, извлечение модов+тиров+affix.
4. **Слой 3 — шаблон базы** (`base-template.ts`) — частота модов + лучший достижимый тир + преф/суфф (affix из буквы тира API). `recommend` → keep / improve (твой мод ниже тира) / add (частые, которых нет) с физибилити по свободным слотам.
5. **Слой 5 — метод** (`strategy-prompt.ts` + `strategy-client.ts`) — Claude **через локальный CLI на подписке** (НЕ OpenRouter — решение владельца, тестим локально) объясняет метод крафта (эссенция/экзальт/аннул/…) + приблизительную вероятность поверх детерминированных рекомендаций.
6. **Хранилище** (`signature.ts` + `price-history.ts`) — персист истории цен (localStorage).

### Ключевой разворот vs v2-план
**Цена листинга в poe2-трейде — шум** (рынок бимодален: transmute-джанк + mirror-витрины, среднего нет; хорошие предметы слиты по номиналу). Поэтому value-by-price (diff/value-driver из плана) **отвергнут**; ядро — **частота модов + тиры** (price-independent). Текущую цену предмета отдаём штатному прайс-чеку EE2 (Ctrl+D).

### trade2 GOTCHAs (выяснены и обойдены)
- fetch ≤ 10 id/запрос (иначе «Invalid query») → батчинг.
- search отдаёт макс 100 id; count-группа — только домены explicit/implicit/pseudo.
- язык `query.type` должен совпадать с endpoint (`useEn` как в price-check), иначе «Invalid query».
- Claude/подписка: НЕ `--bare` (ломает OAuth); `--system-prompt` + cwd=temp для изоляции.

### Как запустить (локально, «для себя»)
```sh
cd renderer && npm i && npm run make-index-files && npm run dev   # vite :5173
cd main && npm i && npm run dev                                   # electron overlay
```
Затем в PoE2: Ctrl+E на предмете → «Собрать шаблон» → рекомендации; «Метод от Claude» — опционально (нужен установленный/залогиненный Claude Code).
Сборка инсталлятора: `cd renderer && npm run build`, `cd main && npm run build && npm run package`.

### Статус
Логика проверена end-to-end на живых данных. **Открыто:** живой smoke в самой игре (наведение на предмет в PoE2 — делает владелец); тюнинг выборки/состава count-группы.
